# Contributing to p2a

Thanks for helping improve p2a. This guide applies to every public repository in [p2a-sh](https://github.com/p2a-sh), unless a repository has its own `CONTRIBUTING.md`.

## Before you start

- **Security issues** go to info@p2a.sh, not to a public issue. See [SECURITY.md](SECURITY.md).
- **Questions about the hosted service** (accounts, invites, the private beta) go to info@p2a.sh. The [guides](https://p2a.sh/guides) and [FAQ](https://p2a.sh/faq) may answer them first.
- **Bugs and feature requests** go in the issue tracker of the repository they concern. Search the open issues first.

## Pull requests

1. For anything larger than a small fix, open an issue first so we can agree on the approach.
2. Fork the repository, create a branch, and keep each pull request to one change.
3. Add or update tests, and run the repository's test and type-check commands (listed in its README) before you push.
4. Write clear commit messages and describe *why* in the pull request.
5. Never commit tokens, keys, or real message content. Use placeholders such as `P2A_TOKEN` in examples and tests.

By contributing, you agree that your contribution is licensed under the license of the repository you contribute to.

## Code of Conduct

Everyone taking part must follow our [Code of Conduct](CODE_OF_CONDUCT.md).
